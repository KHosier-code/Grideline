TASK B — SLEEPER PLAYER IDENTITY MAPPING + COVERAGE VALIDATION

Goal:
Map Sleeper NFL players to existing Gridline players safely and measure mapping quality before Sleeper is used for depth-chart interpretation.

Task A is complete and provides:
- immutable Sleeper player snapshots
- daily worker-owned sync
- all 32 active NFL teams represented
- 12,227 current Sleeper rows in development
- 1,524 players with depth_chart_order
- Data Health sync visibility

This task must NOT change production model behavior.

HARD SAFETY RULES

Do NOT:
- retrain any model
- refit any model
- promote any model
- alter Phase 6.1 features
- change prediction generation
- rewrite historical predictions
- overwrite nflverse history
- force ambiguous player mappings
- expose raw Sleeper payloads to consumers

TASK 1 — CANONICAL TEAM NORMALIZATION

Normalize Sleeper team labels to Gridline canonical team identities before player matching.

Requirements:
- support all current NFL abbreviations
- explicitly handle legacy/team aliases such as OAK -> LV where appropriate
- preserve the original Sleeper team value for audit
- do not treat a legacy alias by itself as a player identity conflict
- do not rewrite Sleeper source snapshots

Return:
- original Sleeper team code
- normalized Gridline team ID/code
- normalization method

TASK 2 — PLAYER IDENTITY MATCHING HIERARCHY

Map Sleeper players to Gridline players using the strongest available evidence.

Priority:

1. Exact provider ID / cross-provider ID match
2. Exact known external-ID crosswalk
3. Normalized full name + normalized team + compatible position
4. Normalized name + strong supporting evidence only when team/position changes are explainable
5. Otherwise mark ambiguous or unmatched

Use provider IDs if Sleeper supplies identifiers such as:
- GSIS
- ESPN
- Sportradar
- Yahoo
- Rotowire
- other stable external IDs

Do not rely on name matching when an exact ID is available.

TASK 3 — NAME NORMALIZATION

Support common player-name variations safely.

Handle:
- Jr / Sr
- II / III / IV
- apostrophes
- hyphens
- periods
- initials
- extra whitespace
- accents/diacritics where appropriate
- common abbreviation differences

Examples should remain distinguishable when they refer to different players.

Do not merge two players solely because their normalized names are similar.

TASK 4 — POSITION NORMALIZATION

Normalize compatible position aliases without overmatching.

Examples:
- PK -> K
- DE / EDGE where existing Gridline taxonomy requires interpretation
- DB should not automatically equal CB or S without supporting evidence
- OL should not automatically equal OT/G/C when that would create ambiguity

Preserve:
- original Sleeper position
- normalized Gridline position
- position compatibility result

TASK 5 — MAPPING RESULT MODEL

For each Sleeper player derive:

- sleeper_player_id
- mapped_gridline_player_id
- mapping_status
- mapping_method
- mapping_confidence
- original_team
- normalized_team
- original_position
- normalized_position
- evidence summary
- ambiguity reason if applicable
- unmatched reason if applicable

Use explicit statuses such as:

- exact_provider_id
- exact_crosswalk
- normalized_name_team_position
- supported_name_match
- ambiguous
- unmatched

Do not use a vague generic "matched" status.

TASK 6 — TRADE / TEAM-CHANGE HANDLING

Do not create false mismatches when a player recently changed teams.

When Sleeper team and Gridline historical team differ:

- prefer stable provider identity if available
- inspect current roster/team evidence
- preserve both source values
- record team-change evidence
- do not silently rewrite historical Gridline records

A current team mismatch with a stable exact player ID should not invalidate identity.

TASK 7 — DUPLICATE / COLLISION PROTECTION

Detect cases where:

- two Sleeper players map to one Gridline player
- one Sleeper player has multiple possible Gridline matches
- duplicate normalized names exist on the same team
- same-name players exist league-wide

Do not choose arbitrarily.

Mark these as conflicts requiring explicit evidence.
