## Proposed database change

- **Production migration required: yes.** The proposed Publish schema diff adds exactly two empty, additive tables and three indexes. It is a schema-state diff; the development-only `0037` runner is **not** a second production step.
- `red_zone_player_game_facts`: required text `game_id`, `source_game_id`, `season_type`, `player_id`, `team_id`, `opponent_team_id`, `source`; required integer `season`, `week`, `zone`, `targets`, `carries`, `receiving_touchdowns`, `rushing_touchdowns`; nullable text `player_name`, `position`; nullable `timestamptz source_updated_at`; required `timestamptz ingested_at`. Counters default 0, `source` defaults `nflverse_pbp`, `ingested_at` defaults `now()`. Composite PK `(game_id, player_id, team_id, zone)` is also its uniqueness rule; checks restrict zone to 5/10/20 and all four counters to nonnegative values. Indexes `(season, season_type, player_id, week)` and `(season, team_id, zone)`.
- `red_zone_team_game_facts`: the corresponding required game/source/season/week/type/team/opponent/zone/source/time fields, nullable `source_updated_at`, and nonnegative integer `targets`/`carries` with 0 defaults. Composite PK `(game_id, team_id, zone)` is its uniqueness rule; zone/count checks; index `(season, season_type, team_id, week)`.
- **Foreign keys: none** in either DDL or the proposed diff. No prerequisite table must be created for these DDL statements, but runtime reconciliation depends on pre-existing canonical schedules, identity/stat/snap evidence and current-season PBP. Index statements depend on their respective CREATE TABLE statements. No current production rows in these new tables can be overwritten because they do not exist. Review the **actual interactive Publish diff again** before approval; this report is not a guarantee that a later diff is unchanged.
