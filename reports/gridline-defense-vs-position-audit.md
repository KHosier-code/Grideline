# Defense vs Position — source audit and completion record

Scope: read-only, observed regular-season history for QB/RB/WR/TE. No forecast, player-to-defender assignment, betting pick, production write, or publish.

## Initial read-only audit (development, September 26, 2026)

- `games`: schedule game ID, season, week, kickoff, home/away team IDs, `STATUS_FINAL`. In the connected development read view, 2026 Weeks 1 and 2 had 16 final games each; Week 3 had one final game. Only final regular-season Weeks 1–18 with kickoff strictly before the requested cutoff qualify. A queried matchup is itself excluded.
- `teams`: schedule IDs and canonical abbreviations. NFLverse player rows do **not** have the schedule game ID. Resolve by season + week + canonical offense/opponent pair, validated against both schedule sides. Normalize historic/team aliases (including LA/LAR) through the existing usage mapping. Retain the GSIS `player_id` for player identity, rather than grouping by names; a traded player's team/opponent is resolved on each game row.
- `player_game_stats`: successful stored NFLverse `player_stats` imports, season/week, `REG`, GSIS player ID, position, team/opponent, QB `attempts`, `passing_yards`, `passing_tds`, `interceptions`, `rushing_yards`, `rushing_tds`; RB `carries`, rushing/receiving yards and TDs, `targets`, `receptions`; WR/TE targets, receptions, receiving yards and TDs. All of these are actual source columns mapped by the existing parser, not inferred from a team total. A null value on a matching-position row makes **that metric** unavailable for the game; absent position rows or an unidentified position make the position unavailable. An identified row with recorded zero production can contribute a verified zero. Zero is not inferred from a missing file or a PBP team row alone.
- `team_game_stats`: NFLverse PBP-derived team rows use a different source game ID, so they cannot be joined directly to schedule `game_id`. `red_zone_team_game_facts` and `red_zone_player_game_facts` carry the verified schedule game ID, source game ID, season, week, team/opponent, zone, counts, nullable `source_updated_at`, and `ingested_at`. A matching inside-20 team fact for **both** offenses supplies completed-game PBP corroboration. Inside-20/inside-10 carries or targets additionally require both matching zone-specific team facts and a resolved position on every credited player fact in that offensive game/zone. Position-level red-zone outcomes do not include QB red-zone counts without verified support. Facts with unidentified credited participants or a missing zone are unavailable, not zero.
- `snap_counts`: game ID and offense-snap participation are stored, but some IDs are PFR IDs and require a verified GSIS/PFR crosswalk. This view does not attribute defensive allowances from snaps; the separate existing Player Usage endpoint handles player appearance evidence. Personnel/injury context is not a reliable declaration that a player will start or is healthy, and the UI makes neither claim.
- Source timestamp semantics: NFLverse weekly-stat `source_updated_at` is assigned by the **local import**, not a publisher-provided revision time. Red-zone facts' `ingested_at` is local ingestion; nullable `source_updated_at` is publisher time when available. The response keeps `sourceUpdatedAt: null` rather than mislabeling import time. Results require stored player/fact import timestamps strictly before the display cutoff. Reimports overwrite earlier rows, so historical views may lose coverage rather than reconstruct an earlier source revision.

No database write, migration, source fetch, or development import was needed. An independently attested application database identity was therefore **not** used to authorize a write; no write was attempted.

## Calculation and consumer contract

For each defense and position, select its completed same-season defensive games. For each metric, sum verified opposing player rows **inside each game**; divide the sum across selected covered games by the number of distinct covered defensive game IDs. `season`, `last3`, and `last5` select all or the latest three/five **covered** games respectively. Missing completed games since the earliest selected covered game (or all when no game is covered) retain their exact game IDs and weeks. Outside-window earlier covered games are not mislabeled missing. No postseason, previous season, future result, or result imported at/after the cutoff enters the computation.

The read-only `/api/consumer/defense-vs-position` endpoint returns season, regular-season marker, cutoff, window, source and ingestion clocks, unsupported-field reasons, each defense/position/metric's label and unit, total, per-covered-game value, completed/covered game counts, covered weeks, omitted weeks and game IDs, and partial/unavailable reason. The OpenAPI-generated client is used by the existing Game Detail and the sortable league table. Each request batches local season reads; a cached batch is invalidated by final schedule changes, successful source-import changes, and stored stat/red-zone row count or ingestion revision changes. No player-level upstream request occurs on page load.

## Observed development coverage and manual arithmetic

At the September 26 development read cutoff, 33 final regular-season games represented **66 defensive team-games**. The response covered **60 of 66** team-games for each supported QB/RB/WR/TE weekly-stat metric, across 31 defenses; per-position inside-20/inside-10 metrics covered **29 of 66** team-games across 29 defenses. The remaining game/week IDs and any per-metric partiality are returned per defense rather than interpolated. These numbers are a snapshot, not a claim of source coverage for other seasons. In particular, the Week 3 final had no stored matching red-zone team facts and contributes neither a stat zero nor a red-zone zero.

## Verification, changes, limitations

- Focused pure tests cover multiple WR rows in a single defensive game, source-missing, absent position rows, ambiguous position, partial imports versus observed zero, latest covered three/five and missing-week labels, cutoff/game exclusion, postseason, LA/LAR aliases and traded team rows, separate rushing/receiving TDs, and partial inside-10 coverage. API and web TypeScript checks passed; the generated OpenAPI contract passed codegen. Live read-only API returned metric-specific values, invalid-window 400, and an empty pregame-cutoff sample; desktop and mobile league previews rendered in the existing dark theme. The upcoming Game Detail preview showed both sides and their observed, covered metrics.
- Files: new `artifacts/api-server/src/lib/defense-vs-position.ts` and its focused test; changed API route/build entries, `lib/api-spec/openapi.yaml` and generated client/types; new `artifacts/nfl-analytics/src/components/DefenseVsPosition.tsx`, plus Game Detail, App navigation, and stylesheet changes; this report.
- Discrepancies corrected: direct `team_game_stats.game_id` versus schedule game ID would have dropped all coverage, so the verified red-zone team mapping is used. A frontend timestamp formatter combined mutually incompatible Intl options and crashed the league page; corrected and rechecked by screenshot.
- Remaining limitations: historical imported source versions are not retained, so a later import can make a past cutoff unavailable. A conservative missing/ambiguous red-zone participant can suppress position-level red-zone coverage even when team PBP exists. The existing red-zone opportunities endpoint is feature-gated and returned 503 in the development preview; this new read-only derived view uses already-stored facts and does not change that gate. No supported air-yards, routes, play efficiency, named receiver–cornerback matchup, or individual injury/start confirmation is inferred.
