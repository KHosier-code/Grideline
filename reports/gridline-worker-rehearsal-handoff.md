## Reproduce in a fresh disposable cluster

From the workspace root, run `bash scripts/rehearse-worker.sh`. It refuses an occupied reserved port, creates a new PostgreSQL data directory under `/tmp`, listens only on `127.0.0.1:55429`, creates **only** `gridline_rehearsal`, generates an independent cluster system ID and random database-comment marker, applies the current schema to that empty cluster, seeds sanitized fixtures, starts the **actual worker entrypoint** in rehearsal mode, records before/after SQL state, runs the real prediction writer and authoritative-kickoff selector, and stops and removes the cluster. The script overwrites only `reports/gridline-worker-rehearsal-results.json`, never a live database URL. Do not source a live `.env` into the script.

The rehearsal entrypoint checks all switches and URL format **before importing the database pool**. It then checks the connected database name, cluster system identifier, database marker, and loopback server address **before ownership or preparation**. Any missing, invalid, or contradictory value aborts. Rehearsal refuses normal worker approval and worker-tick ownership. It permits network sockets only to its exact local PostgreSQL port; all other sockets and `fetch` fail, and any `setInterval` fails. The worker asserts no denied socket, fetch, or timer attempts; it acquires and releases ownership in the disposable cluster, runs the genuine scheduler preparation/recovery SQL, and closes the pool. Neither independent feed scheduling nor retention initialization is entered. Normal worker mode still requires its separate `GRIDLINE_NEW_WORKER_APPROVED=1` gate and existing ownership lock; rehearsal flags are refused in normal mode.

## Ordered live development restart procedure — handoff only, NOT executed

1. **Get operator authorization and a fresh inventory.** Investigate the last exit only from already retained logs if available; absence of a cause is not a safe-to-start signal. Confirm the worker workflow is still stopped. In an explicitly authorized read-only development session, inventory `scheduler_jobs` by key/kind, overdue and future due times, active leases, `data_sync_runs` (`scheduled:*` attempts included), retention age/deletion scope, current schedule and kickoff changes, feature readiness and last saved odds credit metadata. Compare with the 92-key *historical* baseline, not as an assumed current count. Stop if any lock is active, a freeze is newly due, or a new job cannot be explained.
2. **Verify the binding in the actual intended worker environment before allowing writes.** Have the operator independently attest the runtime's non-secret database identity (database name, server identity/system identifier, environment class and an approved cluster fingerprint) against the intended development database identity. Do not print, paste, hash into reports, or change connection strings. A read-only query from another environment, the production replica, or a matching database name alone is insufficient. Stop if the workflow's runtime identity cannot be verified or differs. Keep production credentials and URLs out of the workflow.
3. **Disposition freezes explicitly.** Inspect all 17 historical keys and every newly discovered legacy or canonical key against *current authoritative kickoff* and saved official snapshots. Expired ones must have `enabled=false`, `next_run_at=NULL`, `last_status=skipped` and a per-key run reason; do not rearm or backfill them. Preserve prior pre-kickoff snapshot input/market JSON and already frozen official rows. Verify any future canonical occurrence still points to its current cutoff; stop if a historical key could become claimable or if a kickoff flex is inconsistent.
4. **Authorize activity separately.** Obtain explicit operator approval for free ESPN/Sleeper/NFLverse/NWS contacts, DB feature/model jobs, independent immediate feed attempts and Usage Lab retention deletions (including age and expected volume). Obtain **separate explicit paid Odds API authorization and spending limit**, based on current approved quota evidence, not the historical 494-credit observation. If any category is not approved, do not start the normal all-loops worker; rehearsal flags are *not* a substitute for a selective live-run mode.
5. **Choose normal mode deliberately.** Remove *all* `GRIDLINE_WORKER_REHEARSAL` and `GRIDLINE_REHEARSAL_*` settings from the worker workflow. Only after steps 1–4, enable the existing `GRIDLINE_NEW_WORKER_APPROVED=1` approval/ownership path and start the **configured Gridline data worker** once. Do not use the disposable script against the live DB. Confirm only one worker owns the lock and no old worker build overlaps.
6. **Observe and stop on deviation.** Immediately observe startup logs, fresh skip/rearm audit rows, upcoming due times, independent `scheduled:*` attempts, retention state and provider request ledger. Stop the worker if binding/ownership changes, a past freeze becomes enabled, an old occurrence executes, retention exceeds the approved scope, any unapproved provider call occurs, paid credits exceed the authorized budget, or failures repeat. Stopping the process ends new scheduling; inspect in-flight work before assuming a stop reversed it.
7. **Post-start verification.** Reconcile every original and newly created job against the new inventory; verify the 17 freeze skip records and unchanged snapshot evidence. Check genuinely observed game-matched odds and fresh cutoff-safe paired feature rows before expecting writer output. If the writer creates a row, check exact currently promoted versions, finite ordered 27-vector, source evidence, schema fingerprint, prediction timestamp before authoritative kickoff, selector eligibility, and market eligibility separately. Do not use old snapshot backfill, synthetic quotes, or consumer selection-policy changes to populate Home.

This is an operator-controlled procedure, **not permission or a request to restart**.
