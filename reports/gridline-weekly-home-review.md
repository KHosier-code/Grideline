## Why development says “Updating”

1. `GET /api/consumer/dashboard` invokes `consumerGames()` (`artifacts/api-server/src/routes/consumer.ts`), which reads future scheduled/pregame games from persisted `games`, then asks `getLatestValidPredictionSnapshots()` for a **pregame**, authoritative-kickoff, as-of eligible saved snapshot. It does not compute or save a prediction.
2. Snapshot selection (`artifacts/api-server/src/lib/live-predictions.ts`) requires the three currently promoted production families to share the expected feature schema and valid immutable artifacts. Candidate rows must match their exact versions, vector/schema fingerprint and input evidence, have complete finite inputs and outputs, and precede the saved game's kickoff. A raw snapshot count is not an eligible snapshot count.
3. In the inspected development environment, the dashboard returned **46** future games across weeks 3 onward, **zero** returned predictions, all data-confidence labels `Updating`, and `availability.prediction = "Prediction pending — incomplete model inputs"`. The next actual slate is **2026 week 3 (15 games)**. Development has 165 raw prediction snapshots, including 80 for the full week (75 for the 15 future games). The rows use the same `pregame-v3` feature-version *name* as the promoted models, but older phase-4 or phase-6-refit model versions. Critically, they have `input_feature_count = 0`, no input vector, source evidence, or schema fingerprint. `input_missing_feature_count = 0` is **not** proof of complete inputs when the total feature count is zero. All three production families have promotion rows. Thus these historical snapshots fail both the exact model-version and input-integrity filters. The generic API availability message does not distinguish these causes.
4. The API's `confidence(undefined)` produces `Updating` and “Prediction data is being refreshed”; it is not evidence of a refresh in progress. The old shared card showed that label in its header and used `availability.prediction ?? 'Updating'` for projection; `formatQuote(null)` also returned `Updating`, while the old Home gated spread through recommendation eligibility. The revised Home, Games, and Game Detail do not interpret these strings as a live calculation. The development API reports schedule and odds feeds **stale**, spread comparison `absent`, and no eligible spread; Home states separately that the feeds are stale and that no saved odds exist for a matchup.
