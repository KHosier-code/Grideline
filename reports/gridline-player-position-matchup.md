# Player-position matchup: evidence and release boundary

Version `position-context-descriptive-v1` (comparison), `player-position-forward-research-v1` (historical evaluation). Development-only analysis, September 26, 2026. No production data, schema, promotion gate or official game model was changed.

## Definitions and contract

- Upcoming regular-season Game Detail only. A candidate is a GSIS player ID **plus the offense team** on a verified, completed schedule game in the same season. The choice does not assert current roster assignment, active status or starting status. A traded player's earlier team appearances never become appearances for the new team. Schedule matches require season, week, canonical team and opponent; ambiguous schedule matches are excluded.
- QB: pass attempts, passing yards, passing TDs, rushing yards and rushing TDs. RB: carries, rushing yards and TDs; targets, receptions, receiving yards and TDs. WR/TE: targets, receptions, receiving yards and TDs. Passing TDs are not rushing/receiving scoring TD probability.
- Player totals include only observed numeric values from verified appearances in the selected **last three/five offensive team games** or season; per-game divides by that metric's covered player appearances, not the team's games. A recorded zero counts; no row or null does not. `requestedGames`, `coveredGames`, `coveredWeeks` and `missingWeeks` report the difference. The defense is *all opposing players of the position*, not the selected player's expected output: its total sums covered defensive team-games, and per-game divides by those games. The inherited defense `last3`/`last5` windows take the most recent **covered** defensive games, flagging missing intervening weeks, whereas the offensive player window takes the latest scheduled team-games. These are separately labeled denominators, not a common sample or the same opponent schedule.
- A final schedule state and kickoff before the request are required. Current imports with a local `sourceUpdatedAt` after the request are excluded; verified red-zone facts require both offense and defense game rows. `sourceUpdatedAt: null` indicates no archived publisher timestamp. Import time is displayed separately; historical feed revisions are overwritten, not reconstructible as-of an old kickoff. `cutoff` is the selected game's scheduled kickoff; `asOf` is the read time.
- The descriptive index is centered near 50 and bounded to 0–100: `50 + 20 × (player yards/appearance ÷ max(1, player yards/appearance + role opportunities/appearance) − 0.5) + 100 × defenseAdjustment`, rounded and clipped. QB role is pass attempts and yardage passing yards; RB role is carries and yardage rushing yards; WR/TE role is targets and yardage receiving yards. `defenseAdjustment = clip((opponent position yards/covered game ÷ max(1, opponent position yards/covered game + player yards/appearance) − 0.5) × 2 × 0.2 × n/(n+5), −0.2, 0.2)`, with `n` covered defensive games. Higher means stronger observed production plus a modest opponent context; this is **not** a trained predictor or a named defender matchup. It is withheld unless role and yards each have at least three covered appearances and 75% offensive team-game coverage, and the opponent has at least three covered defensive games and 75% defensive game coverage.
- Each projected metric has an independent null reason, model version and pregame cutoff fields. No targets, yards, carries, passing TDs or expected scoring-TD count has a qualified live model here. Recent observed averages are labeled comparisons, never filled into the projection value; no league baseline is fabricated. The separate weekly at-least-one *rushing or receiving* TD pipeline is read only through its existing development readiness gate and matched on exact player, offense, defense, game and earlier-than-kickoff cutoff. Its probability stays unavailable when that gate blocks; it is never represented as an expected TD count. The score is not promoted as predictive.

## Forward-only research and holdout

Run `pnpm --filter @workspace/api-server run player-position:evaluate:dev` against the development database to regenerate the machine-readable [evaluation](gridline-player-position-evaluation.json). The 2025 regular season was split into weeks 1–9 for training and weeks 10–18 for the forward holdout. Historical *game chronology* is respected: each player baseline uses up to five earlier appearances with the same team; a league/position baseline uses only prior observed rows; a potential defensive position total is assembled from prior games with both PBP team rows and available position stat rows. Kickoff batches are processed together. Null targets and yards are excluded, never converted to zero. Each metric/position reports training and holdout `n`, defense-covered `n`, MAE, RMSE, bias and three predicted-value calibration buckets; the paired player-only/defense-context ablation is evaluated on identical eligible rows. Candidate defense weights 0, 0.1, 0.2 and 0.4 are selected by training MAE and shrunk by `n/(n+5)` with a 25% adjustment cap. This is a research exercise, **not** a source-publication-time backtest, model artifact or live release approval.

The 2025 research history has **no qualifying defensive-context games** in this read view (`defenseTrainingN = defenseCoveredN = 0` for every metric), so the defense weight is 0 by construction. Its ablation error is null, **not** zero or proof of improvement. There are 378 unreconciled stat rows, 4,216 insufficient-history metric observations and 10,050 observations with incomplete defensive coverage; these counters are exclusions, not imputed outcomes. For TE receiving yards, the held-out player-only calibration buckets contain respectively 185/186/186 appearances: low predictions 5.69 yards versus actual 9.88, middle 20.32 versus 22.44, high 47.12 versus 40.41. These errors and the missing defensive ablation do not support a live yardage or targets release. No TD count model was trained or assessed by this research.

The current-season sample (two completed team-games before the Week 3 matchup below) also falls short of the three-game index minimum. Imports do not retain pregame publisher release versions, and per-player roster/injury/starter evidence has not passed a current freshness gate. These are independent blockers for any live count even if a historical MAE looked attractive. The earlier historical player-yards simulations remain simulations, not a substitute.

## Verification and remaining limits

Focused matchup tests exercise cutoff exclusion, zero/null, two TEs in one defensive game, partial PBP, team/game reconciliation, trades, appearances versus team-games and the separate TD gate. Generated API/Zod/client contracts and API/web TypeScript checks pass. The live development API returned the TE trace above with null forecast and index. The existing red-zone HTTP fixture test requires a development test environment and was not run as part of the non-mutating checks. No general data backfill, sportsbook output, named defender assignment or production change was attempted.
