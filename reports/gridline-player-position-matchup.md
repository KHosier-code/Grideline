# Player-position matchup: evidence and release boundary

Version `position-context-descriptive-v1` (comparison), `player-position-forward-research-v3` (publisher-verified historical evaluation). Development-only analysis, September 26, 2026. No production data, promotion gate or official game model was changed.

## Definitions and contract

- Upcoming regular-season Game Detail only. A candidate is a GSIS player ID **plus the offense team** on a verified, completed schedule game in the same season. The choice does not assert current roster assignment, active status or starting status. A traded player's earlier team appearances never become appearances for the new team. Schedule matches require season, week, canonical team and opponent; ambiguous schedule matches are excluded.
- QB: pass attempts, passing yards, passing TDs, rushing yards and rushing TDs. RB: carries, rushing yards and TDs; targets, receptions, receiving yards and TDs. WR/TE: targets, receptions, receiving yards and TDs. Passing TDs are not rushing/receiving scoring TD probability.
- Player totals include only observed numeric values from verified appearances in the selected **last three/five offensive team games** or season; per-game divides by that metric's covered player appearances, not the team's games. A recorded zero counts; no row or null does not. `requestedGames`, `coveredGames`, `coveredWeeks` and `missingWeeks` report the difference. The defense is *all opposing players of the position*, not the selected player's expected output: its total sums covered defensive team-games, and per-game divides by those games. The inherited defense `last3`/`last5` windows take the most recent **covered** defensive games, flagging missing intervening weeks, whereas the offensive player window takes the latest scheduled team-games. These are separately labeled denominators, not a common sample or the same opponent schedule.
- A final schedule state and kickoff before the request are required. Current imports with a local `sourceUpdatedAt` after the request are excluded; verified red-zone facts require both offense and defense game rows. `sourceUpdatedAt: null` indicates no archived publisher timestamp. Import time is displayed separately; historical feed revisions are overwritten, not reconstructible as-of an old kickoff. `cutoff` is the selected game's scheduled kickoff; `asOf` is the read time.
- The descriptive index is centered near 50 and bounded to 0–100: `50 + 20 × (player yards/appearance ÷ max(1, player yards/appearance + role opportunities/appearance) − 0.5) + 100 × defenseAdjustment`, rounded and clipped. QB role is pass attempts and yardage passing yards; RB role is carries and yardage rushing yards; WR/TE role is targets and yardage receiving yards. `defenseAdjustment = clip((opponent position yards/covered game ÷ max(1, opponent position yards/covered game + player yards/appearance) − 0.5) × 2 × 0.2 × n/(n+5), −0.2, 0.2)`, with `n` covered defensive games. Higher means stronger observed production plus a modest opponent context; this is **not** a trained predictor or a named defender matchup. It is withheld unless role and yards each have at least three covered appearances and 75% offensive team-game coverage, and the opponent has at least three covered defensive games and 75% defensive game coverage.
- Each projected metric has an independent null reason, model version and pregame cutoff fields. No targets, yards, carries, passing TDs or expected scoring-TD count has a qualified live model here. Recent observed averages are labeled comparisons, never filled into the projection value; no league baseline is fabricated. The separate weekly at-least-one *rushing or receiving* TD pipeline is read only through its existing development readiness gate and matched on exact player, offense, defense, game and earlier-than-kickoff cutoff. Its probability stays unavailable when that gate blocks; it is never represented as an expected TD count. The score is not promoted as predictive.

## Forward-only research and holdout

Run `pnpm --filter @workspace/api-server run player-position:evaluate:dev` against the development database to regenerate the machine-readable [evaluation](gridline-player-position-evaluation.json). The 2025 regular season was split into weeks 1–9 for training and weeks 10–18 for the forward holdout. Historical *game chronology* is respected: each player baseline uses up to five earlier appearances with the same team; a league/position baseline uses only prior observed rows. Defense history requires a uniquely reconciled completed schedule game, successful season-specific player-stat and PBP imports, PBP rows for both teams, stat rows for both teams, non-null values for every player of the position, and a one-to-one match between the offense's PBP and stat player IDs for that position. Kickoff batches are processed together. Null targets and yards are excluded, never converted to zero. Each metric/position reports training and holdout `n`, defense-covered `n`, MAE, RMSE, bias, and predicted-value calibration buckets for the full player baseline and both arms of the paired cohort. Candidate defense weights 0, 0.1, 0.2 and 0.4 are selected by training MAE and shrunk by `n/(n+5)` with a 25% adjustment cap. A missing training cohort has a **null** fitted weight, not a fitted zero.

Successful weekly-stat and PBP ingestion captures an immutable, fingerprinted local release of the season's player stats, PBP-derived game/team/player identities, schedule and source receipts. The import records the SHA-256 of each source file's compressed bytes. At capture, the file must still match that digest and GitHub's authoritative release API must identify an asset with the same URL, size and SHA-256 digest. Asset ID, API URL, publisher `created_at` and `updated_at`, file digest and size are saved inside the release fingerprint. If the asset was replaced, the API is unavailable, or the local bytes differ, that dataset receives **no** publisher attestation. A GitHub tag timestamp or local import time alone never proves the file version existed at kickoff. Older local archives without these attestations remain readable but cannot qualify.

For each scored game, **both** exact file assets must have their last publisher update strictly before scheduled kickoff, and the application's immutable capture must also predate kickoff. The independent `archivedAsOf` comparison selects the last qualifying snapshot, computes player/league/defense features from that version alone, and uses a later final stat row only as the outcome. The primary scored cohort now uses only those qualifying archived examples, not reconstructed rows from today's overwritten files. The reconstructed game-time loop still counts missing evidence for diagnostics, but it cannot score a forecast. The weekly scoring-TD pipeline is separate and unchanged. This publisher proof does not itself certify current roster assignment, injury freshness, or model promotion.

## Verification and remaining limits

Current cutoff eligibility is a separate fail-closed check for the selected GSIS player and offense: a unique recent GSIS-to-ESPN identity, a verified complete current ESPN team roster with an affirmative active status, a verified game-specific active roster for the exact game, and recent explicit injury clearance must agree on identity and team. Each assertion must be observed no later than the request cutoff, strictly before kickoff, and within 48 hours of the request; injury publication must also precede the observation and cutoff. Missing, stale, uncertain, inactive, conflicting and post-cutoff evidence fails. The current ESPN injury feed is injury-only, not an affirmative healthy-player feed, and the data model has no game-specific active roster capture, so **no selected player currently qualifies** even when a complete team roster exists. This check only refines a withheld reason; it cannot enable any count. The evaluation reports independent release blockers for sufficient publisher-verified chronology coverage, same-cohort defensive coverage/calibration, and current eligibility; a few qualified historical examples alone cannot remove these blockers.

Focused matchup and evaluation tests exercise cutoff exclusion, zero/null, two TEs in one defensive game, partial PBP, missing identity, paired calibration, missing publisher evidence, byte-digest mismatch, later-than-kickoff archive exclusion, trades, appearances versus team-games and the separate TD gate. The development migration applied and the linked JSON was regenerated: the 2025 training and holdout cohorts are both **zero** in v3; errors and fitted weights are null. No general data backfill, sportsbook output, named defender assignment or production change was attempted. Targets/yards remain unavailable in the consumer API regardless of evaluation results; the separate weekly scoring-TD pipeline is unchanged.
