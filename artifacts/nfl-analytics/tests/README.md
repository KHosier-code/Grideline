# Theme and keyboard browser checks

Run the web and API workflows first, then `pnpm test:theme`. This runs the signed-out desktop/mobile checks against the routed preview (`http://localhost:80` by default). Set `GRIDLINE_TEST_BASE_URL` if the routed app is elsewhere. Chromium is used from the Replit toolchain when available, otherwise from the standard Playwright installation.

To check Admin, supply `GRIDLINE_ADMIN_STORAGE_STATE=/absolute/path/to/authorized-clerk-state.json pnpm test:theme:admin`. Capture the state with Playwright's `context.storageState({ path: ... })` from a **real, already-authorized development Admin session** for the same origin; the file contains live session credentials. Do not commit it, share it, or use a production account. The Admin command fails if no state is provided or if the session is not authorized. It does not set claims, alter `ADMIN_USER_IDS`, or mock authorization responses. Refresh expired state from an authorized session when needed.

Run `pnpm --filter @workspace/nfl-analytics run test:teams-browser` with the web workflow running to check Team Evidence cutoffs and out-of-order responses in Chromium. The test mounts the real page on a test-only entry and intercepts only the team analytics API; it needs no live account or API worker.

Run `pnpm --filter @workspace/nfl-analytics run test:usage-browser` with the web workflow running to check Player Usage discovery, sort, shared-link reload, reset, and privacy-safe analytics in desktop and mobile Chromium. The test-only entry mounts the real page and intercepts the usage, schedule, and analytics endpoints; it needs no account, API worker, or live player data.

The public theme check also writes desktop (1280px) and mobile (390px) screenshots for Home, Teams, Defense vs Position, and signed-out Saved Games in both themes to its ignored `test-results/` folder. It checks active navigation, no horizontal overflow, persisted theme, keyboard focus, and reduced motion. Orange is reserved for brand and selections; warning/error/success keep semantic tones, and multi-series charts retain separate teal, violet, gold, and rose colors.

Visual review exceptions: the public browser run has no signed-in Clerk session, so it cannot photograph populated Saved Games; the authenticated route uses the same header and existing `ConsumerGameCard` content/follow control, but needs an authorized development session for a live populated review. In the September 26, 2026 development preview, Home showed its existing data-unavailable state because the API could not find `initial_weekly_picks`; no data or schema was changed as part of this visual task.
