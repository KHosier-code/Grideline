# Theme and keyboard browser checks

Run the web and API workflows first, then `pnpm test:theme`. This runs the signed-out desktop/mobile checks and then provisions a one-use Clerk development user for the real Admin authorization gate and desktop/mobile Admin checks. The release validation workflow runs this same command. It requires development Clerk keys and the local routed preview (`http://localhost:80`). Chromium is used from the Replit toolchain when available, otherwise from the standard Playwright installation.

For only the Admin check, run `pnpm test:theme:admin`. No shared storage-state file or account is required. The runner creates a Clerk development identity with random credentials, signs in with a 90-second ticket, grants its exact user ID development-only Admin access for at most ten minutes, and removes the identity, grant, and private temporary browser state afterward. Production and live Clerk keys cannot use the temporary grant. If Clerk, the API, or the session expires, the check fails rather than skipping Admin. Do not enable Playwright traces for the Admin suite or print session state.

Run `pnpm --filter @workspace/nfl-analytics run test:teams-browser` with the web workflow running to check Team Evidence cutoffs and out-of-order responses in Chromium. The test mounts the real page on a test-only entry and intercepts only the team analytics API; it needs no live account or API worker.

Run `pnpm --filter @workspace/nfl-analytics run test:usage-browser` to check Player Usage discovery, keyboard access to the ordering explanation, sort, shared-link reload, reset, and privacy-safe analytics in desktop and mobile Chromium. Playwright starts and stops a dedicated local Vite server; it fails if the test port is already occupied rather than using another server. The test-only entry mounts the real page and intercepts the usage, schedule, and analytics endpoints; it needs no account, API worker, web workflow, or live player data. The `usage-browser` routine validation runs this command.

Run `pnpm --filter @workspace/nfl-analytics run test:supported-charts` with the web workflow running to check lazy Game Detail plots as evidence appears and as market and sportsbook filters change. Its test-only entry mounts the real chart components with deterministic evidence and needs no account or API worker. The production performance budget separately checks that a sparse live Game Detail does not download either plot.

The public theme check also writes desktop (1280px) and mobile (390px) screenshots for Home, Teams, Defense vs Position, and signed-out Saved Games in both themes to its ignored `test-results/` folder. It additionally photographs signed-in Saved Games populated, empty, loading and error component states at both widths and themes via `/tests/saved-games.html?state=populated|empty|loading|error`. That test-only entry renders the production view and game cards with synthetic, contract-typed matchups and the actual save-control markup; it has no Clerk provider, account, credentials or network-backed follow mutations and is not part of the production build. The suite checks cards, projection/market labels, save-control toggling, retry, links and horizontal overflow. It checks active navigation, no horizontal overflow, persisted theme, keyboard focus, and reduced motion. Orange is reserved for brand and selections; warning/error/success keep semantic tones, and multi-series charts retain separate teal, violet, gold, and rose colors.

Visual review exceptions: the fixture checks signed-in layout, not live Clerk authorization or persistence. A live populated Saved Games review still needs an authorized development session. In the September 26, 2026 development preview, Home showed its existing data-unavailable state because the API could not find `initial_weekly_picks`; no data or schema was changed as part of this visual task.
